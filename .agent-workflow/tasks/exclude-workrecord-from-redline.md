# Exclude the Work Record folder from redline classification

**Outcome:**
The agent-redline reporter no longer classifies the agent-workflow bookkeeping folder (`.agent-workflow/**`) as a review surface. Work Record files land in the `excluded` bucket instead of the `gray` catch-all, so a genuinely-Routine PR is no longer forced to `detected_risk >= Elevated` by the mere presence of its own Work Record. The Routine/compact tier becomes reachable. `dist/` is regenerated and the suite is green.

**Target:**
This repo. Source-of-truth under `core/…`; generated copies in `dist/` and the installed skill dirs regenerated by the packager.

**Scope:**
- `core/agent-redline/core/reporter/reporter.py`:
  - Add module-level `_DEFAULT_EXCLUDES = (".agent-workflow/**",)` + helper `_effective_excludes(policy)` returning `[*_DEFAULT_EXCLUDES, *(policy.get("excludes") or [])]` (additive merge, not replace).
  - `classify_files()` and `_pr_size_status()` both source their excludes from `_effective_excludes(policy)` so they share one merged list.
  - `classify_files` docstring notes the built-in default; `_DEFAULT_EXCLUDES` comment documents the custom-`taskPath` caveat.

## Implementation

Fixes the self-referential risk-classification bug where a task's own Work Record (`.agent-workflow/tasks/{slug}.md`) lands in the gray catch-all and forces `detected_risk >= Elevated`, making the Routine/compact tier unreachable for any workflow PR. Fix is a reporter-level additive default exclude of `.agent-workflow/**`, so the bookkeeping folder is `excluded` rather than classified. No red-zone/schema touch; no architecture-review checkpoint. Deliberately leaves this repo's stale `.agent-workflow/tasks/**` blue entry in place (the default supersedes it) to avoid editing the red-zone policy file for a cosmetic cleanup.

## Plan review

Clean-context agent review (read-only; no prior context from the implementation session).

**Verdict: sound.** The fix is correct, complete for the conventional layout, well-tested, and does not weaken a real safety property. Verified independently (reviewer ran the full suite green and reverted the fix to confirm the tests actually guard it):
- Excludes are evaluated first with a `continue`, so an excluded path physically cannot fall into red/blue/gray, and the watch tag (after the `continue`) is not applied to excluded paths.
- `_effective_excludes` is additive (`[*_DEFAULT_EXCLUDES, *(policy.get("excludes") or [])]`); both `classify_files` and `_pr_size_status` source from it, so they cannot diverge.
- The emitted verdict zones carry only red/blue/gray/watch — `excluded` is never emitted — so the checker's `detected_risk()` (which keys Elevated off `zones.get("gray")`) sees an excluded WR drop out of risk derivation with zero checker change. This is the crux and it holds.
- Safety preserved: WR *content* validation is entirely independent (checker `workrecord.*`/`markers_present` predicates); redline never inspects WR content.
- Reverting the two call sites failed 5 reporter tests (excluded-by-default, excluded-over-blue, additive-merge, PR-size, WR-only-diff-BLUE) — non-tautological.
- Vendoring integrity confirmed: `dist/` + installed-skill copies byte-identical to `core/`; `manifest.txt` sizes match; `package` drift check passes.

**Nits (documented, no change required):**
- Custom `taskPath` outside `.agent-workflow/` isn't covered by the folder-keyed default → documented `policy.excludes` workaround in the reporter comment and the template.
- The checker test `test_work_record_only_diff_detected_routine` is tautological w.r.t. the reporter fix; its docstring says so and points to the reporter-side proof (`test_work_record_only_diff_is_not_gray`).
- Leaving the redundant `.agent-workflow/tasks/**` blue entry in the red-zone policy file is the right call (harmless dead config; editing it would trip the architecture-review gate for a cosmetic change).
