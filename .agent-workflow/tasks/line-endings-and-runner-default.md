**Discovery:**

- `package-skill.sh` writes substituted markdown as LF (`newline="\n"`) but `cp`s templates/schemas/scripts/hooks verbatim → those inherit source CRLF; `manifest.txt` records `wc -c` byte counts (CR-inflated). This mixed handling is the mechanical root cause of dist's CRLF.
- `tests/package/check-package.sh` uses `diff -r --strip-trailing-cr` → line-ending-agnostic; only `manifest.txt` byte counts are ending-sensitive → dist must be regenerated (not hand-edited) so the manifest matches.
- Only substantive template change since initial release = artifact v3→v4 (already in `core/`). `runs-on: [self-hosted]` has been the template default since initial release; the repo's own CI and every extension scaffold use `ubuntu-latest` → self-hosted is an internal-context carryover, wrong as a public default. `docs/INTEGRATION.md` documents it and needs reframing.
- `python3` is broken on this machine and `package-skill.sh` hardcodes it → use the `/tmp/pyshim` python3→CPython shim to run the packager + tests.

**Material assumptions:**
- Assumption: `git -c core.autocrlf=false add --renormalize .` converts the CRLF blobs to LF under the existing `eol=lf` attributes. Disproof: `git cat-file` still shows CRLF in staged blobs. Action: fall back to an explicit on-disk rewrite (real CPython strips `\r` over tracked text files) then `git add`.
- Assumption: regenerating `dist/` from LF-normalized sources yields an all-LF dist whose `manifest.txt` matches actual bytes. Disproof: `package` drift or a manifest size mismatch. Action: refresh the working tree to LF (`git checkout -- .` post-renormalize) so the packager reads LF, rerun it, re-add.
- Assumption: the renormalize introduces no semantic diff. Disproof: `git diff --ignore-cr-at-eol` (vs HEAD) shows changes beyond `manifest.txt` numbers + the intended template/doc edits. Action: inspect and revert any non-line-ending change.
